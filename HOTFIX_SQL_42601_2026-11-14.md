# DeltaTV — Hotfix do erro SQL 42601 (Pix Master e Commerce)

## Erros corrigidos

- `GET /api/v1/admin/network/master-pix/orders`: `pgCode=42601 position=191` causado por `:status=''` na query `adminOrders` de `master-pix.service.js`.
- `GET /api/v1/admin/commerce/master-plans`: `pgCode=42601 position=432` causado por `:kind='master'` na query `listPlans` de `commerce.service.js`.
- Prevenção no fluxo `commerce.changeSubscriptionState`, onde também havia `:state='active'`.

No Sequelize 6, a sintaxe de *replacements nomeados* exige delimitadores válidos imediatamente depois de `:parametro`. Os parâmetros colados ao sinal de igualdade podem não ser substituídos e então causam erro de sintaxe no PostgreSQL.

## O que muda

Apenas espaçamento SQL para permitir o reconhecimento de parâmetros nomeados (`:status = ''`, `:kind = 'master'`, `:state = 'active'`). Não há mudanças de preço, pagamento, débito, banco de dados, migrações ou regras de acesso. Preserva o hotfix anterior do import de `MAX_CLIENTS_PER_PARTNER` e do diagnóstico SQL.

## Aplicar em sua VPS

**Faça backup** antes de sobrescrever arquivos em `/var/www/backend-deltaTV`:

```bash
cd /var/www/backend-deltaTV
mkdir -p "$HOME/deltatv-backup-sql-$(date +%Y%m%d-%H%M%S)"
BK=$(find "$HOME" -maxdepth 1 -type d -name 'deltatv-backup-sql-*' | sort | tail -1)
mkdir -p "$BK/src/modules/distribution" "$BK/src/modules/commerce"
cp -a src/modules/distribution/master-pix.service.js "$BK/src/modules/distribution/"
cp -a src/modules/commerce/commerce.service.js "$BK/src/modules/commerce/"
```

Transfira `DeltaTV-backend-hotfix-sql-42601.zip` para a pasta do backend, então:

```bash
cd /var/www/backend-deltaTV
unzip -o DeltaTV-backend-hotfix-sql-42601.zip
node --check src/modules/distribution/master-pix.service.js
node --check src/modules/commerce/commerce.service.js
node --test tests/regression/sql-bindings-42601.test.js
pm2 restart DeltaTV-Server --update-env
pm2 logs DeltaTV-Server --lines 100
```

**Atenção:** o ZIP completo é para desenvolvimento/homologação. Prefira o hotfix de dois arquivos na VPS para minimizar alterações.

## Como verificar

Após atualizar, abra no painel do Superadmin **Pix do Master → Pedidos** e **Planos SaaS → Planos**. As rotas devem retornar 200 quando o esquema do banco estiver atualizado e os dados forem válidos. Se aparecer `42P01` (tabela ausente) ou `42703` (coluna ausente), verifique o estado das migrações em homologação antes de alterar o banco.

Testes neste pacote: sintaxe e verificações estáticas; consultas reais dependem de PostgreSQL e dados de homologação, não foram executadas aqui.
